# Migrations
<!--raw-typst <migrations> -->


Status: **Implemented**.

## Decision


Migrations are generated by comparing the built schema with the recorded
database state. They are deterministic, immutable once applied, and never
edited by hand.

## Rules


- A state file records the SQL of every table, trigger and view the migrations
  create.
- New objects are created. A changed table is rebuilt: create the new table,
  copy the columns it keeps, drop the old table, rename the new one.
- Views and triggers are dropped before a table rebuild and created again last.
- Objects no longer in the schema are dropped.
- An unchanged schema produces no migration.
- Each applied migration is recorded in `__migrations` and never changes.
- The `serve` command refuses to start when the schemas differ from the fingerprint
  recorded by the `init` command.
- CI generates migrations twice and fails if the second run finds changes.

## Consequences


Database changes are reviewable as SQL and repeatable from an empty database.
The tests apply every migration, so generated SQL is exercised rather than
assumed.
